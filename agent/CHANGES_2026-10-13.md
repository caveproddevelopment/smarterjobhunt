# Ingestion agent — 2026-10-13 fix release

Based on Aatish's 7 Oct analysis (`data/indian_companies_zero_jobs_findings_2026-10-07.csv`,
655 Indian companies with 0 jobs) and the 7 Oct Railway logs. Production entry point is
unchanged: `python run_ingestion_db_async.py`. Only the async pipeline was changed; the old
sync pipeline (`run_ingestion_db.py`, `ingestion_orchestrator.py`, `career_scraper.py`) still
runs but gets only the shared ATS detection/API fixes.

## Deploy, in this order

1. **Database** (Railway Postgres; safe to re-run):
   ```
   psql "$DATABASE_URL" -f db/migrations/2026-10-13_listing_status.sql
   psql "$DATABASE_URL" -f db/fixes/2026-10-13_india_findings.sql
   ```
   The migration adds `companies.listing_status`, `listing_status_note`,
   `listing_status_updated_at` and `careers_url`. Copy the migration into
   `backend/db/schema.sql` too. The agent still runs before the migration is applied
   (it checks for the columns first).
2. **Code**: replace the agent folder on Railway with this one. No new packages.
3. **Test run first**, scoped to the Indian list:
   ```
   python run_ingestion_db_async.py --company-type indianmajor --results-csv india_retest.csv
   ```
   Then compare `scrape_company_results` for the new batch with the 7 Oct batch
   (query at the bottom).
4. **Control run on US companies**: `--company-type funded --limit 300`, compared with
   the last funded run. These changes apply to every company, not just Indian ones.

## What changed

### Bugs that affect every company, not just India
- **Ashby has returned 0 jobs for every company.** The code read `jobPostings`,
  `departmentName`, `locationName` and `publishedDate`, but the public API returns `jobs`,
  `department`, `location` and `publishedAt`. I checked this against `jobs.ashbyhq.com/bolna`,
  which has 5 live jobs. The name-slug probe looked for the same wrong key, so it never
  matched either. Both fixed. Expect a jump in US startup jobs.
- **Ashby board names were cut short.** Names with dots or `%20` were truncated, which is
  where the 7 Oct log 404s for `ashby/The`, `ashby/Local`, `ashby/Gray` and similar came from.
- **Workday URLs were garbled.** URLs inside HTML-entity or JSON-escaped page source were
  cut off, producing `https://opportunities&#34;...` and `https://nmyworkdayjobs.com` in the
  logs. Page source is now unescaped before scanning.
- **`--company-type midsize` matched nothing.** The DB check constraint says `midmarket`.
  Both names are now accepted and stored as `midmarket`.

### New hiring-platform API adapters (`agent/ats_api.py`)
Greenhouse EU (Groww), Lever EU, Workday, SmartRecruiters (Freshworks), Oracle Recruiting
Cloud (Berger, Havells, Fortis, Tejas and 9 others) and Recruitee. Workable falls back to
its v1 widget endpoint. Where the list endpoint has no description, a per-job detail call
fills it (capped at 60 per company), because staging auto-approve needs 100+ characters of
`raw_text`.
**Not live-tested from my environment**: Oracle, SmartRecruiters detail calls, Workable
detail, Recruitee. Workday was tested against the documented request and response shape
only. Watch `ats_api_error` rows on the first run.

### Scraper (`agent/async_career_scraper.py`, new `agent/platforms.py`, `agent/job_json.py`)
- **Page validation.** Images, 404 pages served with status 200, `/error` routes, login
  pages, parked domains, age gates, bot walls, redirects to the homepage or to an
  unrelated site, and pages with no careers wording at all are now rejected. The agent
  then moves on to the next way of finding the careers page.
- **Platform hand-off.** If a careers page redirects to, iframes, or links out to a known
  hiring platform (about 60 hosts, including Darwinbox, Keka, PeopleStrong, SenseHQ,
  ZingHR, Kula, Zoho Recruit and TurboHire), the agent follows it, using the API when
  there's an adapter and a second scrape otherwise.
- **iframes.** Links are now read from every frame.
- **JSON capture.** The JSON a page loads while rendering is recorded, and job lists are
  pulled out of it. This is how jobs are read from JavaScript job boards whose listings
  aren't plain links (Darwinbox, Keka and the like).
- **Faster link collection.** All links are read in one in-page call per frame instead of
  two calls per link (Ceat's page has 1,069 links), capped at 1,500 per frame.
- **Waits.** The agent waits for network activity to settle (up to 6s) instead of a fixed
  2s, plus one extra wait if the page is still an empty JavaScript shell.
- **Link filter.** "Apply" / "View job" links are kept when the URL is a job-detail URL,
  titled from the job card's heading or the URL slug. Whole-card link text is cut down to
  the title. More nav noise is rejected ("Life at X", "Benefits", "Skip to content"...).
  Replaying 353 previously scraped links: 300 kept, the 53 dropped were all junk.
- **HTTP/2 errors** (Honeywell, Yes Bank, Policybazaar, EA, Lululemon...) get one retry on
  a second browser with HTTP/2 turned off.
- **Careers discovery.** More path guesses (`/career`, `/recruitment`, `/our-people`,
  `/life-at-<slug>`, `.html` variants, `/en/careers`...), then `sitemap.xml`, then the
  browser homepage scan. The scan now understands Hindi link text (कैरियर, नौकरी, भर्ती),
  "People & Culture", "Recruitment", "Drive your career" and similar. Sites that answer 200
  for any path are detected and handled.

### Orchestrator
- `companies.careers_url` (set by the fix SQL for 146 Indian companies) is tried first.
  Automatic detection only runs if the override produces nothing.
- A rejected or empty careers URL now falls back to browser homepage discovery instead of
  ending the company.
- Each ATS API fetch has its own 60s cap. The per-company cap went from 150s to 210s.
- New outcome stages in `scrape_company_results`: `website_unreachable`,
  `website_ssl_error`, `website_parked`, `blocked_bot_wall`, `scrape_invalid_page` and
  `scrape_http2_error`. When more than one URL was tried, `detail` ends with
  `attempts=[url -> outcome ...]`.
- Companies whose `listing_status` isn't `active` are skipped (310 Indian companies after
  the fix SQL: 249 with no online listings, 35 that only publish PDF notices, 26 needing
  review). To re-check them monthly, use `--listing-status active,no_online_listings`.
  `--companies-file` ignores status.

## Deliberately not done
- **PDF recruitment notices** (30 PSU and bank companies plus 5 moved banks): waiting on a
  product decision. They are set to `pdf_notices` and skipped.
- **Indian proxy for Power Grid**: costs money for one company.
- **Cloudflare and perfdrive challenges**: not bypassed, only classified as
  `blocked_bot_wall` for manual review.
- **Global parent boards** for Indian subsidiaries (Colgate, Cummins, Honeywell,
  Schaeffler, GE Vernova, ABB): no override set, because they would import worldwide jobs
  under the Indian company's name.
